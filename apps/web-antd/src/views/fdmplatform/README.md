# 业务协同平台：部门菜单接入

这是当前 Vue 3 / Vben / Ant Design Vue 管理端内的 FDM 业务扩展。源代码只位于 `api/fdmplatform` 与 `views/fdmplatform`；不替换共享登录、请求客户端、布局或既有业务页面。

## 正式接口与共用业务范围

请求使用当前 `requestClient`、正式登录身份及租户头，业务基址为 `/fdmplatform/v1`。生产 API 沿用现有 `/admin-api` 同源配置；不使用演示用户或模拟资料。后端仍验证当前租户启用用户，并保留版本冲突、业务状态、数量金额和历史证据校验。

本业务全部启用登录用户可执行完整的合同、采购、报关、库存、财务及资料维护流程；不按公司、岗位、部门或负责人隔离。页面不再提供公司范围切换、岗位授权或初始化授权流程。`/access.sharedAccess=true` 表示业务共用，`superAdmin` 仍反映真实系统身份；普通用户不会被赋予现有系统的超级管理员角色。

列表、产品、销售价格、客户、供应商、仓库、货权、库存、规则与人员目录统一使用内部共用范围 `companyId=0`。零值是共用查询标记，页面正常加载和编辑，不代表可选择的签约公司。数据仍保留当前系统租户边界。

合同新建必须从 `/access.companies` 选择真实“订单所属公司”，保存实际公司编号。编辑保留已有公司，不用共用范围覆盖订单属性；停用公司的历史合同也保留原显示。合同列表、部门单据列表及合同详情展示订单公司，查询不会按公司过滤。单据动作由已选合同 ID 关联其实际公司。

新建及标准编辑合同必须明确选择产品分类：瑜伽系列产品、鼠标垫地垫产品、健身系列产品、攻防箭系列产品。旧合同缺少分类时列表及详情显示“未分类”，不自动推断；迁入合同也可通过“补齐合同办理资料”仅填补缺少的分类。

客户编号首次保存由系统生成，原有编号只读保留。国家 / 地区从 `/customers/options` 的 249 个 ISO 选项选择，支持中文、英文、二字码、三字码及接口提供的常见别名搜索，不能新建自由国家值；历史非标准值原样提示，维护保存前须重新选择。`customerSource` 是展会、转介绍等业务来源，区别 `sourceSystem` 的资料来源；`companyName` 可人工维护。OKKI 预览展示公司及来源资料并核对国家，刷新保留系统编号、本地业务来源、备注与启用状态。

业务列表通过本模块 `compact-tables.css` 限定样式：单元格上下各 8px，名称与摘要至多双行，长文本省略且可悬停查看，操作区保持单行与横向滚动，不修改宿主或官方模块表格。


每个部门有独立的服务端分页列表。合同、采购申请、履约任务、报价、方案、采购订单、回款、发票和成本调用各自 `/page` 接口，支持页码、关键词、状态及可选经办人筛选，默认显示全部。采购申请使用 `assignmentStatus` 筛选分派状态，成本使用 `status` 筛选归集阶段；金额不跨币种合并。

合同详情只显示概要、产品明细、流程进度、关联单据导航、合同附件和审计。后续办理在各类单据独立列表完成，不再打开包含所有采购和财务操作的万能抽屉。关联导航携带 `?contractId=实际合同ID`，列表可清除筛选并恢复全部记录；新建时预选该合同，未指定时通过服务端分页搜索选择合同，客户和订单所属公司只读带入。

专用办理仅展示当前类型动作及当前单据明细，行操作重新读取合同并锁定真实源单 ID、最新合同版本与方案版本。来源事件标识自动生成，同次提交和失败重试保持稳定。凭证可在办理窗口直接上传后选择。表单按申请/申请明细、订单/订单行、方案/方案行、履约任务/报价、库存池/预留或发货流水联动筛选；服务端继续校验状态、版本、数量和金额。当前单据流程暂不启用审核。合同保存草稿后可直接生效，采购方案经业务校验直接生效，生效后再分别办理下单、预留和自产；修订后需要重新生效。历史审核记录保留，不再作为办理节点。

采购待办默认打开“待接单申请”，通过 `/purchase-intake/page` 显示有效且还有履约分派余量的申请，可从申请行直接“接单 / 分派”；第二个“履约任务”页签使用原 `/assignments/page`。待接单判定按申请明细数量减去未取消的真实履约分派数量计算，不能把已有负责人等同于数量全部分派。部分分派后仍保留余量，全部分派后退出待接单列表。表单锁定来源申请，只有一条剩余明细时自动预选并带入精确剩余量，允许修改本次分派数量。

新增分页资源为 `arrivals`、`purchase-returns`、`production-progress`、`outbound-shipments`、`sales-returns`、`receipt-records`、`receipt-refunds`、`allocations`。回款与退款冲销、发货与销售退货各用独立后端类型过滤；旧无 kind 快照按同一服务端兼容规则识别。没有现行业务模型的回款计划、付款、换货和佣金不生成空菜单。

## 自建产品中心与合同选品

产品中心独立维护本合同业务自己的产品，只保留“产品档案”和“销售价格”两个页面。所有启用登录用户均可在此新建并维护编号、名称、规格、材质、尺寸、颜色、单位、标准印刷和包装；已有编号保持稳定，资料版本由服务端维护。聚水潭或其他历史 SKU 不进入本产品目录，也不参与新合同选品；产品资料导入页面和专用来源、导入 API 已移除。

合同新建及修订使用专用宽抽屉。合同编号只读，首次保存由服务端分配 `HT-yyyyMMdd-六位日序号`，创建请求不携带人工编号，编辑保留既有编号。选择订单所属公司、客户和币种后，从产品中心服务端分页搜索并跨页多选，一次带入规格、单位、标准资料及匹配的销售参考价。业务员行内填写数量、成交价和交期，按需展开定制图稿与包装。外贸部门新建默认“外贸 B2B”，编辑时保留原业务类型。重复 SKU 保留独立行，可复制明细；已有采购申请的规格继续受服务端保护。

未匹配价格显示待定价并允许保存草稿，确认合同前补齐价格。更换币种或税费口径会清空旧价格，需要显式重新匹配参考价或填写成交价。产品版本 `0` 为有效版本，历史 `null` 版本明细沿用原引用；产品后续维护不会重写历史合同快照。

产品资料、销售参考价和标准资料向全部启用登录用户开放维护，跨订单公司共用。产品档案支持二次确认删除；服务端按版本检查合同、库存及采购分派引用，有引用时拒绝删除并提示停用。未引用产品删除后不再进入产品、销售价格或合同选品，内部历史和文件仍保留。产品标准资料使用独立私有附件抽屉，支持版本替换及历史下载；客户专属图稿应在具体合同中上传。合同引用的标准资料通过合同下载接口读取，身份验证及历史引用保持有效。

## 采购报关与财务协作

“采购部门 → 报关跟进”负责批次创建、责任分派、资料准备、办理状态及异常补件。同一合同可分多个批次，带入合同产品与采购订单，关联真实出货数量；上传报关资料支持分类、历史版本、预览和下载。

合同流程页展示采购、出货、报关、回款与开票进度，并跳转采购部门独立报关页面，自动筛选当前合同。报关费用经人工核验后按凭证归集；上传商业发票或报关完成不会自动确认回款或重复开票。回款、发票和报关各自记录实际业务进度。

## 外贸客户管理与 OKKI

外贸部门新增客户管理页，使用共用的 `MASTER_CUSTOMER` 档案；本地新增、联系信息维护、启用和停用后，合同客户选择直接读取同一资料。客户编号及全称必填，联系人、地址、网站、邮箱、电话等可补充。停用客户不改写历史合同快照。

OKKI 接口只读远程资料，状态接口不返回凭据。按关键词搜索采用服务端有界分页扫描，页面累计保留已找到客户并提供“继续查找”；未扫描的远程数据不会被当作无结果。外部客户 ID 始终按字符串处理。选取后先读取预览，可对比当前本地档案，再凭预览哈希、当前版本和稳定幂等标识确认同步。已同步客户可再次预览刷新：名称、编号及联系资料被最新来源覆盖，本地备注和启用状态保留。来源主要联系人或首位联系人选择提示一并显示。

## 财务汇率与回款人民币折算

汇率中心按日期调用 `/fx-rates` 查询，支持主动抓取指定日期及筛选币种。展示查询日期、实际来源日期、抓取时间、来源链接以及 `1 原币 = rateToCny CNY`；休市或当日参考值尚未公布时明确显示采用此前日期。当前来源为欧洲央行公开参考值，用于业务折算，不代表银行实际结汇价格。服务端按小时刷新当日参考值。

登记回款时按到账日期、币种和金额调用服务端换算预览。汇率缺失或接口失败时显示错误，不假定汇率为 1 或人民币金额为 0；页面不提供手填折算汇率及人民币金额。保存回款由服务端重新校验并冻结 `exchangeRateToCny`、`exchangeRateDate`、`exchangeRateSource`、`exchangeRateFetchedAt`、`exchangeRateFallback` 和 `rmbAmount`。合同详情与财务回款列表展示这些实际值；历史记录缺少快照显示“待补齐”，通过 `REFRESH_RECEIPT_FX` 补充。已确认且已有快照的回款不因抓取更新而改写，退款、冲销沿原快照按比例形成反向金额。

## 用户目录与历史入口

人员和部门选项从 `/directory?companyId=0` 读取真实启用用户名称和部门，不根据姓名或手机号猜测身份。合同新建默认当前用户及部门作为业务登记属性，可选择其他真实用户。订单所属公司和负责人仍必填；业务部门可选，无部门的启用登录用户也可创建合同，部门下拉允许清空。负责人仅用于分工和可选筛选，不限制读取或办理。采购报关默认全部批次，支持主动筛选“我负责的批次”。

业务岗位授权菜单已停用；兼容组件只说明当前共用流程，不调用授权、撤销或初始化接口，不阻断业务页面。原授权记录保留历史，当前全员业务能力由后端决定。

## 合同附件和业务凭证

新建或编辑合同、采购申请、报价、采购方案、采购单生成、到货、出入库、回款、开票、成本以及采购财务和报关表单，均可在附件区多选或拖入文件。文件在点击保存时与业务数据一起提交，最多10个、单个20MB、总计50MB；保存中禁止关闭或改动队列，失败保留输入和文件供原键重试。无附件时沿用原JSON接口，有附件时使用`/submissions`下对应multipart接口，业务和附件关联在同一事务内保存。

普通单据详情默认显示当前单据附件，可切换查看合同全部附件；采购单管理页有独立“单据附件”页签。使用平台合同附件接口与私有存储，新文件绑定服务端核定的具体单据ID，各资料分类保留业务用途；下载通过带当前认证信息的请求获取文件流，不生成公开API链接。采购财务和报关继续使用各自单据附件及版本规则。

表单中的附件和证据字段可从当前合同附件选择，历史外部凭证仍可保留引用。私有存储未配置时明确显示配置需求，不回退到公开上传。上传有独立幂等标识；合同、库存和财务动作继续携带业务版本和稳定幂等标识。

## 主数据来源与 CSV

旧主数据工具保留外部空白 / 成品 SKU 来源适配和历史映射，以兼容原有资料。它们不属于本次自建产品中心，也不参与新产品目录或新合同选品；主数据页面中的产品入口统一导向自建产品档案。客户、供应商、仓库和货权主体继续按已有主数据职责维护。历史来源身份保持稳定，已有合同快照不会被改写。

UTF-8 CSV 每批 1–200 行、文件最大 2 MB，支持 BOM、双引号、转义及引号内换行。表头：

```csv
type,name,code,externalId,specification,unit
```

前四列必填；类型为 CUSTOMER、SKU、SUPPLIER、WAREHOUSE 或 STOCK_OWNER。编号按文本处理。浏览器计算原始字节 SHA-256，服务端接收映射记录及校验声明，预检后再确认，不覆盖内容冲突的现有映射。原始文件本身应按业务凭证要求保存，不能把声明当成服务端已存储原文件。

## 金智单据原生承接

合同、采购申请、采购单、发货、回款、退款、发票、采购付款及库存资料统一进入现有业务菜单，不再按来源拆分业务入口。列表使用原生服务端分页，原单号、状态、金额和已履约数量保留。没有可靠父合同的单据使用独立原生业务身份，补齐缺项并关联真实来源后继续办理；不得虚构合同、审批或执行记录。

单据详情中的来源信息通过 `/fdmplatform/v1/sources/{kind}/{nativeId}` 分页读取原字段、重复表头、文件/工作表/行号与核对问题；已迁移批次仍能溯源。缺少原币金额或币种时明确展示缺项，原账面金额单独保留，不默认为人民币或零；未随导出表提供的附件说明缺失，不提供假下载。

产品详情统一展示合同、采购、收付款、发票、出入库、盘点及库存流水，按真实单据身份精确跳转。整单采购付款不自动分摊成产品金额。来源库存量与平台可用量分别展示，外部主账库存需真实盘点与货权核实后接管；导入旧出入库单不会重复扣减库存。

合同/单据补齐使用当前版本与幂等标识，原量价与已知资料不能借补齐操作覆盖；采购申请的待分派量扣除原已转采购量。待核实采购付款与退款须确认真实执行和凭据后接续，原水单保留私有下载；未知历史汇率不自动补造。
